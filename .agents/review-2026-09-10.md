# Product and design review — 2026-09-10

## Scope

Reviewed the public landing and login pages, authenticated notes and Kanban workflows, editor, attachments, backup controls, context menus, server ownership boundaries, and existing domain tests. This review improves the existing private notebook rather than adding collaboration, offline synchronization, or new authentication providers.

## Findings addressed

| Finding | Change |
| --- | --- |
| Landing felt like a conventional software overview rather than a distinctly cute notebook | Rebuild around a paper-and-clay desk, expressive Fresh wordmark, notebook playground, and privacy keepsake; carry softer geometry and tactile controls into login, app, dialogs, and error pages |
| Search only inspected the loaded page, and a zero-result search hid pagination | Server search covers the entire owned notebook, including attachment filenames and tags, with debounce, cancellation, stable ordering, and pagination |
| Switching to Kanban destroyed an unsaved note composer | Keep the composer mounted and retain its in-memory content and pending files |
| Changing notes or signing out could discard edits without warning | Confirm discarding changes; protect browser navigation and reload |
| Save completion could clear edits made during an in-flight save | Disable the composer controls during save and attachment upload |
| Preview failure could display HTML from an earlier note | Clear stale HTML and provide an inline error and retry action |
| Backup import defaulted to replacing everything without explaining the consequence | Default to Merge; explain both modes and require a checkbox acknowledgement for Replace |
| Restore refreshes the page and could lose the current draft | Disable restore while a draft or save is pending; keep export available |
| Mobile navigation could compete with a discard dialog for focus | Close the navigation drawer before confirming sign-out; avoid a second native leave prompt after consent |
| Favorite updates left the local list inconsistent with server ordering | Refresh the current query after saving, favoriting, and deleting; prevent repeated favorite clicks during pending updates |
| Empty notebook, empty favorites, request failure, and no search results shared an unhelpful state | Contextual copy, relevant recovery actions, explicit loading, and inline retry |
| Note editing was hidden in an overflow menu | Make the note title an accessible edit button |
| Small type, low-contrast light-theme labels, and competing panel shadows reduced readability | Stronger action/text contrast, 14px rendered text, 15px wrapping titles, lighter composer depth, and clearer workspace/editor headings |
| Destructive confirmations looked different across operating systems | Shared styled confirmation dialog for notes, files, boards, columns, cards, passkeys, and demo actions; Cancel receives initial focus |
| Passkey-first entry did not explain account bootstrap | Login and landing copy explain GitHub first, then passkey registration |
| Unhandled page errors fell back to a generic framework screen | Branded 404/error page with home and retry actions |

## Generated notebook icon

The final mark is a soft-cover blue clay journal with ivory paper edges, a cream ribbon bookmark, and a short sky-blue pencil. The cover is blank, without writing lines or facial features. Rounded proportions and tactile materials establish its cute stationery character while the bound spine and pencil communicate note-taking. Generation used the user-authorized Replicate CLI with the exact model `openai/gpt-image-2.5-flare`, prediction `q584aawtndrmw0d0gwtap0dpwg`, output 1. Two 1024×1024 high-quality opaque PNG variants were inspected. No model substitution was used.

The production master is [`public/fresh-icon.png`](../public/fresh-icon.png). Regular exports crop the selected 1024px source to `(144, 128, 912, 896)`, resize with Lanczos, and apply 218px rounded corners at 1024px. All existing PNG favicon/PWA sizes and the ICO are replaced consistently. Maskable exports use the original opaque composition with wider safe space. Inspected the mark at 16, 32, 48, 64, 128, and 192px and within actual light/dark pages.

Final generation prompt (CLI mode):

> Use case: logo-brand. Design a beautiful, distinctive app icon for Fresh, a personal notebook app. A single charming miniature pocket journal with a plump soft BLUE cover, beautifully rounded corners and a gently rounded bound spine, viewed at a slight three-quarter angle. The front cover is entirely clean and unmarked. Show a clear thick layer of warm ivory paper along the right and bottom edges, with just two or three softly sculpted page layers. A short cream ribbon bookmark peeks out of the bottom with a tiny soft curl. A short rounded sky-blue pencil with an ivory tip is neatly tucked against the journal's right side, partially overlapping it; keep the pencil secondary. The journal should look like a delightful collectible piece of Japanese designer stationery: cute through its compact proportions, soft sculpted shapes, and tactile material, with an elegant uncluttered silhouette. Premium matte clay and soft-touch cover texture, smooth broad highlights, gentle natural contact shadow, carefully art-directed studio product lighting. The overall composition must read immediately as a NOTEBOOK and writing tool at 32px. Retain the Fresh palette: blue #5288e8, sky blue #8eb8fb, pale icy blue #dceaff, warm ivory white. Centered square composition on a solid pale icy-blue backdrop, all meaningful objects inside the central 75% of the canvas, plenty of room for an app-icon mask. No facial features whatsoever: no eyes, smile, eyebrows, cheeks, face, or mascot. No horizontal writing lines, rules, parallel decorative strokes, cover labels, text, letters, numerals, charts, graphs, spiral rings, glitter, sparkles, stars, hearts, flowers, stickers, extra objects, hands, legs, neon, or glossy plastic. Avoid exaggerated perspective and avoid a generic flat vector look. A real small blue notebook, rendered as a polished, lovable clay object.

Raw images, CLI input/result JSON, and the thumbnail contact sheet are local ignored artifacts under `output/imagegen/`.

## Product boundaries

Core private notebook and personal Kanban flows are implemented. Sharing, collaboration, offline sync, conflict resolution, standalone tag management, and manual theme selection remain outside the current product. Drafts are protected during a visit, but are not stored across browser restarts. Search is a substring query rather than an indexed full-text engine. OAuth and real hardware passkey verification require their external credentials/devices.

## Verification

Validation results and browser coverage are recorded in `product-status.md`. Local review uses a disposable user and fixtures in local D1/R2 only. Screenshots, browser scripts, temporary backup files, and generated SQL remain in ignored `output/`; generated production icons are intentionally tracked in `public/`. No production data or remote configuration is changed.
